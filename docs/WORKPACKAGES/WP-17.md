minor (`docs/RELEASING.md` §1). Owns, for this work package only, one

   `docs/decisions/2026-10-02-cross-plan.md` Appendix A. A console or
   portal session token has `iss` (the system's own issuer URL), `aud`

## What to build

```go
// SessionScope is the scope claim of every session token (Appendix A).
const SessionScope = "session"

// SessionClaims are the caller's part of a session token; the issuer
// adds iss, scope "session" and the kid header. Every field is required.
type SessionClaims struct {
	Audience  string
	Subject   string
	Roles     []string
	Realm     string
	IssuedAt  time.Time
	ExpiresAt time.Time
	JTI       string
}

func (i *Issuer) IssueSession(c SessionClaims) (string, error)
```

The payload is exactly, and in this order, `iss`, `aud` (one string),
`sub`, `scope` (`"session"`), `roles`, `realm`, `iat`, `exp`, `jti`:
no `nbf`, nothing else. The header is `alg RS256`, `kid` (the issuer's
key id) and `typ JWT`. Times are whole seconds.

The caller supplies `jti`, `iat` and `exp`, because it keeps the session
row (revocation by `jti`, the idle timeout) and must know them before it
signs. The TTL limit and the idle timeout are the caller's policy and
are not checked here (thresholds are data, CLAUDE.md rule 3); `realm`
is not restricted to the three Appendix A values for the same reason.

Refusals, each a `*core.FieldError` naming the field:

| Input | Field |
|---|---|
| a nil issuer, or one with no `iss` | `iss` |
| an issuer with no key | `key` |
| empty `aud`, `sub`, `jti`, `realm` | that name |
| no roles (nil or empty), or an empty role | `roles` |
| a string that is not valid UTF-8 (JSON would rewrite it) | its name |
| `iat` before 1970 | `iat` |
| `exp` not after `iat` in whole seconds, or after 9999-12-31T23:59:59Z | `exp` |
| a signed token longer than `DefaultMaxTokenBytes` | `token` |

The last four exist so that the promise below holds without exception:
each is a token the verifier would refuse (a NumericDate out of range,
an expired token, an over-long token) or would read back differently
(replaced UTF-8).

**The promise.** Every token `IssueSession` returns is accepted by a
`Verifier` with `StrictSessionClaims` that allows the issuer with its
JWKS and has `aud` as an audience, at any time from `iat` up to `exp`,
and the verified `Claims` carry the given `Subject`, `Audience`, `JTI`,
`Roles`, `Realm`, the issuer's `iss` and `kid`, `Scopes == ["session"]`
and the two times in whole seconds.

What it must not do: change `Issue`, `NewIssuer`, `KeyRing`, the
verifier or any counter. `Issue` keeps writing no `roles`, `realm` or
`typ`. No new counter: like `Issue` and `SignCompact`, a refusal is
returned to the caller, which counts it.

## Tests

- Round trip: a session issued with sub-second times verifies with and
  without `StrictSessionClaims` at `iat` and up to `exp` plus the skew,
  and is `rejected_expired` at `exp` plus the skew; the payload bytes
  are exactly the Appendix A row in order; the header has exactly
  `alg`, `kid` and `typ`.
- A `KeyRing`'s issuer signs with the active kid, verified against the
  ring's JWKS.
- E-01, each refusal beside its accepted twin: one role / no roles;
  `exp` one second after `iat` / equal / same second; `iat` at 1970 /
  before; `exp` at the end of 9999 / past it; a 5000-byte `sub` / one
  that pushes the token past the bound; non-ASCII UTF-8 / invalid UTF-8
  in each string.
- `Issue` unchanged: its token verifies strictly with no roles and no
  realm.
- `FuzzIssueSession` over every field and both times: a refusal is a
  `*core.FieldError` with no token; an issued token verifies under the
  strict verifier at `iat` with exactly the given claims.
- `BenchmarkIssueSession` reported (not added to
  `docs/bench-targets.txt`, like `BenchmarkIssue`).
