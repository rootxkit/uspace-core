# WP-15: `geodesy/cell`, the 0.1° / 1° partition grid (C1)

Branch `feat/WP-15-geodesy-cell`. Milestone C1 (`uspace-core v1.1.0`,
`docs/PLAN.md` §12; reconciliation M35, authority Q-A3, ussp Q2). Owns the
new package `geodesy/cell/` exclusively; touches nothing else in
`geodesy/`. Depends on `v1.0.0` only. Consumers: the authority
(`internal/cell` becomes a thin wrapper; `WP-10 bus-sources-cells`), the
USSP (`internal/cell` likewise; `WP-6 bus-cell-tsdb`, `WP-11
traffic-cpa`). The ANSP and the CISP do not partition.

Part of WP-14's `v1.1.0` release; read WP-14 "The one rule of this
release" first. This package is new, so it is additive by construction:
no existing identifier changes, no vector file changes. It is pinned by
unit tests here, and proposed to the lab as new cases of `geodesy.json`
(see Vectors).

## What to build

Package `github.com/rootxkit/uspace-core/geodesy/cell`.

```go
type Level int                       // Level5 (0.1 degree, "c5"), Level3 (1 degree, "c3")
func (l Level) StepDeg() float64     // 0.1, 1
func (l Level) Valid() bool
type ID struct{ Level Level; LatIdx, LonIdx int }
func Of(p core.LatLon, l Level) (ID, error)          // *core.FieldError on an invalid position or level
func (c ID) String() string                          // "c5:1314:2246"; "" for an invalid ID
func Parse(s string) (ID, error)                     // strict: prefix, two non-negative decimal integers in range, no sign, no leading zeros beyond "0", no spaces
func (c ID) Valid() bool
func (c ID) Parent() ID                              // c5 -> the c3 that contains it; a c3 returns itself
func (c ID) Children() []ID                          // c3 -> its 100 c5 cells in row-major order; a c5 returns nil
func (c ID) Ring1() []ID                             // the up-to-8 neighbours, longitude wrapped; fewer at the polar rows; sorted by (LatIdx, LonIdx)
func (c ID) BBox() geodesy.BBox                      // [south, north) x [west, east) in degrees, east may be 180 exactly for the last column
func (c ID) Centre() core.LatLon
func Cover(b geodesy.BBox, l Level, max int) ([]ID, error)   // every cell that intersects b, sorted; antimeridian-crossing boxes (MinLon > MaxLon) handled; more than max cells -> *core.FieldError "bbox" and a nil slice
const MaxCoverDefault = 10_000
```

Indexing, fixed here and pinned by tests (a change later is a major):

- Longitude is wrapped into `[-180, 180)` first (`core.WrapLonDeg` gives
  `(-180, 180]`; map `180` to `-180`). Latitude must be in `[-90, 90]`.
- `lat_idx = floor((lat_deg + 90) / step)`, `lon_idx = floor((lon_deg +
  180) / step)`, so both are non-negative: `c5` has `lat_idx` in
  `[0, 1799]` and `lon_idx` in `[0, 3599]`; `c3` has `[0, 179]` and
  `[0, 359]`. Latitude `+90` exactly belongs to the last row (clamped),
  so every valid position has exactly one cell at each level.
- Floating point: compute the index with `math.Floor` on the scaled
  value and then correct by one where `p` falls outside the cell's own
  `BBox` (a position on a boundary such as `41.7` must land in the cell
  whose south edge is `41.7`, and `41.7 + 90` scaled by 10 is not exactly
  representable). Tests cover every tenth-degree boundary around
  Georgia's bounding box and `-180`, `0`, `180`, `-90`, `90`.
- Parent: `c3.lat_idx = c5.lat_idx / 10`, likewise for longitude.
- `Ring1` wraps in longitude (column `3599` neighbours `0`) and does not
  wrap in latitude: the first and last rows have five neighbours. No
  cell is ever its own neighbour.
- `Cover` iterates rows then columns over the box's index range,
  splitting a box with `MinLon > MaxLon` into two ranges; it never
  allocates more than `max` entries (count first, then allocate; E-10).
  A box touching `MaxLon == 180` includes the last column once.

Georgia for scale: `41.0..43.6 N`, `40.0..46.7 E` is 27 × 68 ≈ 1 800 `c5`
cells and 4 × 8 `c3` cells; `MaxCoverDefault` leaves room for a
continent-sized query with a hard stop.

Names are the stable wire form (spec `05 §3` as amended): they appear in
NATS subjects and KV keys, so `String` and `Parse` are an exact pair,
`Parse(String(c)) == c` for every valid `c`, and `Parse` refuses anything
`String` never produces (`c5:041:5`, `C5:1:2`, `c5:1:2:3`, `h3:...`).

No I/O, no goroutines, no state. Nothing here judges anything: a cell is
a key, and spec `05 §3`'s rule stands that the partition never crosses an
external interface (`04` messages carry positions, not cells).

## Tests

- The table above; `Parse(String(c)) == c` over every cell of a `c3`
  and over random valid positions; `Parse` refusals, each beside the
  accepted spelling (E-01).
- Boundaries: for every `k` in a range, `Of({k/10, lon})` is the cell
  whose `BBox().MinLat == k/10` (within one ulp of the scaled value), and
  the point is inside `Of(p).BBox()` for 10 000 random positions.
- `Ring1`: count 8 inland, 5 on the first and last rows, wrap at
  columns `0` and `3599`, never contains the cell itself, each neighbour
  shares an edge or a corner (`BBox` adjacency).
- `Parent`/`Children`: every child's parent is the parent; the 100
  children tile the parent's `BBox` exactly.
- `Cover`: a box inside one cell returns that cell; the Georgia box
  returns the expected count; a box crossing the antimeridian returns
  cells from both edges and none in between; `max` exceeded is refused
  without allocating (E-10; test with `max = 1`).
- Invalid input: NaN, ±Inf, latitude past ±90, an invalid level: a
  `*core.FieldError` naming `lat_deg`, `lon_deg` or `level`, never a
  panic.
- `FuzzParse(s string)`: no panic; `Parse(String(Parse(s))) == Parse(s)`
  where `Parse` succeeds.
- Benchmarks `BenchmarkCellOf` (target 100 ns/op) and
  `BenchmarkCellRing1` (300 ns/op), added to `docs/bench-targets.txt`;
  the ingest calls `Of` once per sample (plan §8.6 budget line "same
  path").
