## What to build

### 1. `core.BasisProvider`

```go
// BasisProvider is a flight reported by a USSP through the F3411
// network (display provider) or an F3548 peer: a provider's claim,
// neither an authenticated session nor a broadcast heard by a receiver.
BasisProvider IdentBasis = "provider"
```

That is the whole change to `core`. Nothing in `identify` sets it: the
authority's display-provider ingest sets `Basis` itself on the
`core.Identification` it builds (its own adapter; `identify.Resolve*`
keep returning `as_broadcast` and `authenticated` exactly as today).
Confirm by `grep` that no `switch` over `IdentBasis` exists in the
module (there is none at `v1.0.0`), so `exhaustive` has nothing to flag;
if one appears from a parallel branch, add the case there. No vector
file carries a `basis` field (checked: `grep '"basis"' vectors/testdata`
finds nothing), so no vector can be affected.

### 2. `alerting.Config.SkipConflicts`

```go
// SkipConflicts turns the conflict check off: no neighbour grid lookup
// and no cpa.Evaluate for any sample, so no conflict alert is ever
// raised or refreshed. Zone, height and identification alerts are
// judged as before. For a monitor whose owner discards conflict alerts
// (the authority's violation detector, which raises none). Default
// false. Counted per flying sample under conflict_checks_skipped.
SkipConflicts bool
const CounterConflictChecksSkipped = "conflict_checks_skipped"
```

Behaviour: in `judgeFlying`, when `m.cfg.SkipConflicts` is set, the
sample skips `m.grid.Upsert` and `m.judgeConflicts` and increments the
counter; everything else in `judgeFlying` and `judge` runs unchanged.
`sanitise` leaves the field as given (a bool needs no fix) and
`Monitor.Config()` reports it. With the field false the code path is
byte-for-byte the `v1.0.0` path: the only new instruction is the branch.
`DefaultConfig()` does not set it, so `alert_lifecycle.json` runs as
before.

What it must not do: it must not change clearing. An active conflict
cannot exist under `SkipConflicts`, so there is nothing to clear, and
`Config` is read once at `NewMonitor` with no setter, so a monitor is
either skipping or not for its whole life; a switch at run time would
leave active conflicts with no judgement to clear them. State that in
the field comment. Do not add a setter.

Why not leave the grid in: `cpa.Grid.Upsert` per sample is the
grid's cost, and the authority asked to pay neither it nor `Evaluate`.
`Drop` and the stale sweep call `m.grid.Remove` for an id that was never
inserted; `Remove` on an unknown id is a no-op already (`detach` is
guarded by the `where` map), which the test below proves rather than
assumes (E-02).

## Tests

- `core`: a one-line test that `BasisProvider == "provider"` and that
  it marshals as that string inside `Identification` (the wire form of
  `track/telemetry/v1`).
- `alerting`, E-01 pair: the same two converging tracks fed to a monitor
  with `SkipConflicts: false` raise `conflict` (the existing conflict
  test), and to one with `true` raise nothing while
  `conflict_checks_skipped` counts every flying sample and
  `conflict_pairs_not_judged` stays zero.
- `alerting`, unchanged elsewhere: under `SkipConflicts: true` a track
  entering a PROHIBITED zone raises `zone`; a track over the height
  limit raises `height`; an identification mismatch raises
  `identification_mismatch`; a stale track clears them as `stale`; `Drop`
  clears them with the caller's reason and no panic from the grid.
- `alerting`, the proof of no behaviour change: `TestVectorsAlertLifecycle`
  passes with no edit, and `Monitor.Config().SkipConflicts` is false for
  the vector monitor (assert it once, so a later default change is
  visible in the diff).
- `-race -shuffle=on` green; the existing `BenchmarkMonitorObserve`
  unchanged, plus `BenchmarkMonitorObserveSkipConflicts` reported (not
  added to `docs/bench-targets.txt`: it is a cheaper path of a target
  that exists).
