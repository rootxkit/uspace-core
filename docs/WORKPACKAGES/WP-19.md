# WP-19: memory-mapped geoid and terrain grids (v1.4.0)

Branch `feat/WP-19-geoid-mmap`. Release `uspace-core v1.4.0`, a minor
(`docs/RELEASING.md` §1). Owns, for this work package only, a new
package `internal/mmapfile/`, one new file each in `internal/pgm/`,
`geoid/` and `terrain/` with their tests, the `ParseTile` split described
below, the loader lines of `docs/PLAN.md` §3.4, a paragraph of
`geoid/doc.go` and `terrain/doc.go`, and a non-required CI job. Depends
on `v1.3.0` only.

Read WP-14 "The one rule of this release" first: the rule holds here
unchanged. Nothing that exists changes its output, and no vector file
changes, so the semver gate prints "nothing to gate".

## Why

Every process that converts HAE to AMSL calls `geoid.Load`, which reads
the whole grid into its own heap: `egm2008-2_5.pgm` is 8640 x 4321
samples, 74.7 MB, so each process keeps 71.5 MiB of live heap for the
same read-only bytes, and `io.ReadAll`'s growing buffer leaves more
behind until the runtime returns it (measured on linux/amd64 after
loading and touching every sample: 71.5 MiB live, 169 MiB private RSS).
On the shared droplet several systems run side by side and pay it once
each. DEM tiles (about 26 MB each, up to `MaxTiles` per `Store`) have the
same shape.

A read-only shared memory map (`mmap(PROT_READ, MAP_SHARED)`) puts the
file's pages in the kernel page cache once; every process mapping the
same file shares them, pages are read on first touch, and the kernel may
drop clean pages under pressure and read them again. Nothing is copied
into the Go heap.

## What to build

```go
// internal/mmapfile: the bytes of an open file, mapped read-only where the
// platform can (linux, darwin), read into memory otherwise.
type Mapping struct{ ... }
func Map(f *os.File, maxBytes int64) (*Mapping, error)
func Read(f *os.File, maxBytes int64) (*Mapping, error)   // the fallback, always
func (m *Mapping) Bytes() []byte
func (m *Mapping) Mapped() bool
func (m *Mapping) Close() error                           // idempotent
const Supported bool                                      // per build

// internal/pgm
func ParseFile(f *os.File, maxFileBytes int64, maxBytes int, mapped bool) (*Grid, error)
func (g *Grid) Mapped() bool

// geoid
func LoadMapped(path string) (*Grid, error)
func (g *Grid) Mapped() bool

// terrain
func (t *Tile) Mapped() bool
func MappedDirOpener(dir string, maxBytes int64) func(cell string) (*Tile, error)
type StoreOptions struct{ ...; OpenTile func(cell string) (*Tile, error) }   // new optional field
```

- **Same parse, same numbers.** The mapped bytes go through the same
  `pgm.Parse` and the same geoid and tile checks as `Parse`/`ParseTile`,
  and `UndulationM`/`ElevationM` are not changed in what they compute:
  a mapped grid returns, bit for bit, what the loaded grid returns.
  `ParseTile` is split into `pgm.Parse` plus an unexported
  `tileFromGrid` so both paths share the checks; its output is unchanged.
- **Bounds before the map.** The file must be a regular file; its size
  is checked against the same byte bound `Load` applies (`geoid`:
  `pgm.DefaultMaxBytes` + 1 MiB; `MappedDirOpener`: its `maxBytes`,
  default 64 MiB) before anything is mapped. A truncated file (fewer
  sample bytes than the header's size), a file with trailing bytes and
  an empty file are refused by `pgm.Parse` exactly as from memory, and
  the mapping is released before the error returns.
- **Every index bound-checked.** All sample reads go through
  `pgm.Grid.Raw`, which refuses an index outside the grid and outside
  the bytes. No other code reads the mapped bytes.
- **Lifetime.** A mapping is released when the `*pgm.Grid` that reads
  it is unreachable (`runtime.AddCleanup`), never while a read can be in
  flight: `Raw` keeps its grid alive across the read
  (`runtime.KeepAlive`). There is no `Close` on `geoid.Grid` or
  `terrain.Tile`, so no caller can unmap bytes another goroutine reads;
  a `Store` evicting a mapped tile only drops its reference.
- **Portability.** `mmap` on `linux` and `darwin` through the standard
  library's `syscall.Mmap` (no cgo, no new dependency). On every other
  platform (`windows`, the BSDs, `js/wasm`, ...) `Map` falls back to
  `Read`, which is exactly what `Load` does today, and `Mapped()` reports
  `false`, so a deployment can check which it got.
- **The store.** `StoreOptions.OpenTile`, when set, is used instead of
  `Open` + `ParseTile`; its failures are `tile_read_failed` like
  `Open`'s. With neither set every read fails as before. `Open` alone
  behaves exactly as in 1.3.0.

What it must not do: change `Parse`, `Load`, `ParseTile`, `DirOpener`,
`UndulationM`, `ElevationM` or any counter in what they return; add a
counter (nothing new is refused, dropped or degraded: a refused file is
the same `*core.FieldError` as from `Load`); touch `vectors/testdata/`.

### Operating limit (documented, not enforceable)

A mapped file must not be truncated or rewritten in place while a
process maps it: the kernel then faults the reader (`SIGBUS`), which a Go
program cannot recover from. Replace a grid or a tile by writing a new
file and renaming it over the old one; processes keep the old inode
until they load again. The grids are installed read-only, so this is
the normal way to update them. `geoid/doc.go` and `terrain/doc.go` say
so.

## Tests

- `internal/mmapfile`: a file maps and reads back byte for byte; the
  fallback (forced through an unexported switch, restored after) reads
  the same bytes and reports `Mapped() == false`; an empty file, a
  directory, a file past the bound (refused before mapping, E-10) and a
  file exactly at the bound (accepted, E-01 twin); `Close` twice.
- `internal/pgm.ParseFile`: mapped and read paths agree with `Parse`
  byte for byte; a truncated file, a file with trailing bytes and a bad
  header are refused with the same error as `Parse`, and leave no live
  mapping; an accepted grid's mapping is released once the grid is
  unreachable (live-mapping count goes back down after GC).
- `geoid.LoadMapped`: every sample of the synthetic grid and a dense
  set of positions give bit-identical `UndulationM` to `Load`; heap
  growth while loading a 4 MB grid stays under 1 MiB mapped and is at
  least the grid's size through `Load` (the presence twin); each refusal
  of `Load` is refused the same; `Mapped()` equals
  `mmapfile.Supported`.
- `terrain`: `MappedDirOpener` (cell names cannot escape the
  directory, the bound) agrees with `ParseTile`; a `Store`
  with `OpenTile` answers the synthetic vectors' positions identically,
  counts a failing `OpenTile` as `tile_read_failed`, evicts mapped tiles
  past `MaxTiles` and serves concurrent readers under `-race`.
- `TestVectorsTerrainGeoid` runs each GeographicLib case through both
  `Load` and `LoadMapped` and requires the two results to be identical
  bit for bit as well as within the file's tolerance. The `geoid`
  workflow then exercises the mapped path on the real EGM96 and EGM2008
  grids: all 48 cases of `terrain_geoid.json` pass, none skipped (30 of
  them the GeographicLib references).
- Fuzz: `FuzzParseFile` (internal/pgm) and `FuzzLoadMapped` (geoid)
  write the input to a file and require the mapped path to accept and
  refuse exactly what `Parse` does, with the same error, and to give
  identical samples or undulations when accepted.
- `BenchmarkUndulationMapped` beside `BenchmarkUndulation` (same target,
  300 ns: the prefix in `docs/bench-targets.txt` already matches).
- CI: a non-required job runs `internal/...`, `geoid` and `terrain` on
  `macos-latest` (mmap) and `windows-latest` (fallback), and the build
  job vets the module for `GOOS=windows` and `GOOS=darwin`.
