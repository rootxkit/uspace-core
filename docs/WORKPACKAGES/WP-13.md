## What to build

### The semver gate

`scripts/semver-gate.sh BASE_REF`: on a pull request, if `git diff
--name-only BASE_REF...HEAD` touches `vectors/testdata/*.json` (a changed
expected value, a removed case, or a new file), then:

- `CHANGELOG.md` must add a heading for a **new major** (or, before
  `v1.0.0`, a new minor) under which the changed files are listed with
  the regulation or standard clause behind each (a line matching
  `vectors: <file> (<clause>)`), and
- the PR must carry the label `behaviour-change` (checked through
  `github.event.pull_request.labels` in the job), and
- `vectors/testdata/VERSION` must record a newer `uspace_lab_commit`
  (or the file must be in `local_files`).

Added cases that existing behaviour already passes are additive
(`00 §6.3`): detect them (`cases` count grew, no existing case's
`expected` changed, compared by case name with `jq`) and require only a
CHANGELOG line, no major. Print what it decided and why (E-04).

Add the `semver-gate` job to `ci.yml` (pull requests only; required by
branch protection), and a `tag` job that runs on `v*` tags: verifies the
tag matches the top CHANGELOG heading, that every manifest file has a
vector test (reuse the existing step, now failing), and that `go test
./...` is green; it creates the GitHub release from the CHANGELOG
section (`softprops/action-gh-release` or `gh release create`).

### Consumer proof

`scripts/consumer-check.sh`: creates a scratch module in a temp dir that
`require`s `github.com/rootxkit/uspace-core` at the current commit
(`replace` to the checkout), writes a one-file test calling
`vectors.Load` and `RunOwned(t, "ussp", ...)` on `cpa.json` and runs `go
test -run Vectors github.com/rootxkit/uspace-core/...` from inside that
module, proving that the vectors and testdata travel with the module
(plan §6, §11 gap 12). Run it in CI on tags.

### Documentation

`docs/RELEASING.md`: how to cut a release (CHANGELOG, tag, release
branch), how a behaviour change is made (lab vector first, sync, major,
`release/v<N>` maintained for six months, dual publishing for the
systems), how a system upgrades, and the Go major-version path rule
(`/v2` at the second major). Update `CHANGELOG.md` to its final shape:
`0.1.0` (G-M1, listing every package and vector file), `0.2.0` (G-M2),
`1.0.0` (G-M3: API of plan §3 declared stable; the two added vectors).

## Done when

- [ ] A PR that edits a vector's expected value without the CHANGELOG heading and label fails `semver-gate`; one with them passes; one that only adds cases passes with a CHANGELOG line (prove each with a throwaway branch and paste the job output).
- [ ] `scripts/consumer-check.sh` passes locally and on the tag job.
- [ ] `docs/RELEASING.md` written; CHANGELOG complete; `make ci` green on `main`.
- [ ] The owner tags `v1.0.0`.
