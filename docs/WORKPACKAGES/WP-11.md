Branch `feat/WP-11-auth`. Milestones G-M1 (receiver HMAC, the
`rid_receiver_auth.json` vectors) and G-M3 (the `jwt_verify.json` vector
this package adds). Owns `auth/` exclusively and is the only WP that adds
a dependency (`github.com/lestrrat-go/jwx/v3`, spec `00 §6.2`). Depends
on WP-0 only. Consumers: every system's API processes, the authority's
`rid-ingest`, the token services.

## What to build

### Receiver authentication (R-06; 14 vectors)

```go
func SignReport(key, report []byte) string                  // hex of HMAC-SHA256(key, report)
func Datagram(report []byte, sigHex string) []byte          // report + "\nsig=" + hex
type ReceiverOption func(*receiverOptions)                   // WithNonceMemory(max int), WithNow(func() time.Time)
type ReceiverVerifier struct{...}
func NewReceiverVerifier(keys map[string][]byte, maxSkew time.Duration, opts ...ReceiverOption) (*ReceiverVerifier, error)
type Report struct{ ReceiverID, Transmitter, PayloadHex string; SentAtMS int64; Nonce string; Raw json.RawMessage }
func (v *ReceiverVerifier) Verify(datagram []byte, now time.Time) (Report, error)
func (v *ReceiverVerifier) Counters() *core.Counters        // accepted, rejected_unsigned, rejected_unknown_receiver, rejected_bad_signature, rejected_skew, rejected_replay, rejected_malformed, nonces_evicted
```

Rules: the datagram is the exact report bytes, `\n`, `sig=`, 64 hex
characters; the signature covers the report bytes exactly (no JSON
canonicalisation: `signature-is-hmac-sha256-hex-of-report-bytes`). Parse
the report as JSON **after** locating the signature; refuse (phrases
binding on `accepted` only, but match them anyway): "not signed" (no
`\nsig=`), "unknown receiver 'rx-2'", "bad signature from rx-1"
(constant-time compare), "the signed report is not a JSON object",
"sent_at_ms is not an integer", "sent 31 s from now, more than 30 s"
(|now - sent_at| > maxSkew; 29.9 s either side accepted), "no nonce"
(empty), "nonce repeated by rx-1" (remembered per receiver for twice the
window either side of now; a nonce older than that is forgotten;
`refuse-replayed-nonce-accept-new-nonce`). `NewReceiverVerifier` refuses
an empty receiver id, a key shorter than 32 bytes, or a duplicate id
(B-14 startup error). Nonce memory is bounded per receiver
(`WithNonceMemory`, default 100 000) with oldest eviction counted (E-10).
Document for the ingest: without keys it refuses every report and reports
itself not ready until a key arrives (R-06). uspace-authority's
rid-ingest always listens on its configured address, refuses each batch
with 401 and fails its `/readyz` check `receiver_keys`; a key added at
runtime is accepted without a restart (uspace-authority #36, which
replaced binding loopback only).

### JWT verification (`00 §6.2`, `06 §3`)

```go
type IssuerConfig struct{ JWKSURL string; Keys jwk.Set }     // Keys for tests and static deployments
type Config struct{ Issuers map[string]IssuerConfig; Audience string; MaxSkew time.Duration; JWKSCacheTTL time.Duration; HTTPClient *http.Client; Now func() time.Time }
type Claims struct{ Issuer, Subject, Audience, JTI, KeyID string; Scopes []string; ExpiresAt, IssuedAt time.Time }
type Verifier struct{...}
func NewVerifier(ctx context.Context, c Config) (*Verifier, error)   // defaults MaxSkew 30 s, JWKSCacheTTL 24 h; refuses a non-https JWKS URL except localhost
func (v *Verifier) Verify(ctx context.Context, token string) (Claims, error)
func (c Claims) HasScope(scope string) bool
func RequireScope(c Claims, scope string) error                      // *core.FieldError{Field:"scope"}
func (v *Verifier) Counters() *core.Counters                         // accepted, rejected_issuer, rejected_algorithm, rejected_kid, rejected_signature, rejected_expired, rejected_not_yet_valid, rejected_audience, rejected_claims, jwks_refresh, jwks_refresh_failed
type Issuer struct{...}
func NewIssuer(iss string, key *rsa.PrivateKey, kid string) (*Issuer, error)
func (i *Issuer) Issue(sub, aud string, scopes []string, ttl time.Duration, now time.Time) (string, error)   // iss, aud, sub, scope (space-separated), exp, iat, jti (random), kid in the header, RS256
func (i *Issuer) JWKS() jwk.Set
```

Rules: header `alg` must be RS256 (refuse `none`, HS*, ES*, PS* and an
`alg` that does not match the key); `kid` required and present in the
issuer's JWKS; `iss` must be a configured issuer (allow-list; an unknown
issuer is refused before any network call); `aud` must contain
`Config.Audience`; `exp` required, valid with `MaxSkew`; `nbf`/`iat`
honoured with the same skew; `jti` required; `scope` parsed as a
space-separated string (also accept a JSON array `scp`? no: `scope`
string per `06 §3`; document). JWKS fetched at `NewVerifier` for
URL-configured issuers and cached `JWKSCacheTTL`; an unknown `kid` triggers
at most one refresh per minute (rate-limited, counted); a failed refresh
keeps the cached set (T5: tokens valid to TTL during an issuer outage).
Every refusal is counted by reason and returned as an error whose text
names the claim (`exp`, `aud`, `kid`, ...). Test keys are generated at
test time with `rsa.GenerateKey` (never committed; `06 §4`).

### The `jwt_verify.json` vector (G-M3 deliverable, plan §11 gap 7)

Write `vectors/testdata/jwt_verify.json` in the common shape with
`owners: ["authority","cisp","ussp","ansp"]`, `generated: "hand-written
in uspace-core WP-11 from spec 00 §6.2 and 06 §3; not from utm"`,
`utm_commit` as in `VERSION`, and `fixtures` holding a deterministic RSA
key pair? No: a private key in a public repo is forbidden even for tests
(`06 §4`). Instead the fixtures hold the **public** JWKS and the cases
hold pre-signed tokens whose private key was generated once and
discarded; every case is accept/refuse with a reason: valid; wrong
audience; expired beyond skew; expired within skew (accepted); unknown
kid; wrong issuer; alg none; HS256 with the public key as secret (the
classic confusion attack); missing jti; missing scope then
`RequireScope`; `nbf` in the future. Generate the file with a small
`go run ./auth/internal/genvectors` program (kept in the repo, key
generated at run time, output deterministic given the key), add the file
to `vectors/manifest.go` (`auth`, N cases) and `TotalCases`, list it in
`vectors/testdata/VERSION` under `local_files` (the harness, the sync and
the check scripts already honour that list: such a file is in
`SHA256SUMS`, exempt from the `utm_commit` check and from the online
diff), and regenerate `SHA256SUMS` (`cd vectors/testdata && sha256sum
*.json > SHA256SUMS`). Propose the file upstream to
`uspace-lab/knowledge/vectors/` in the PR description.

## Vector tests

`key_hex`, `report_utf8` -> `datagram_utf8`, `signature_hex` exact; the
others have `keys_hex{id: hex}`, `max_skew_s`, `datagrams[]{utf8, now_s}`

## Other tests

- E-01 pairs for every refusal (vectors cover the receiver side; write
  the JWT side: each refusal beside the accepted token that differs in one
  claim).
- E-02: JWKS refresh failure keeps the old set and counts; an unknown kid
  refreshes once then is rate-limited.
- E-10: nonce memory past its bound; key-set size is the issuer's.
- Concurrency: `Verify` from many goroutines under `-race`.
- `FuzzVerifyReceiver(datagram []byte)` and `FuzzVerifyJWT(token string)`
  never panic; seeded with the vectors.
